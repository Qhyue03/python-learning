## 方法论（v3.1：能力模型对齐，09-03 修订）

**培养的是"人类智力"能力，不是"代码产量"**——代码主要由 agent 生成，人的价值在四项：

| 能力 | 具体表现 | 靠什么练 |
|---|---|---|
| **会使用工具** | VS Code/调试器/Git/conda/厂商SDK 用得顺手 | 每天的工具链使用本身 + w0 热身已建立 |
| **排查问题** | 读报错→定位→假设→验证的循环 | 排障练习（每周一题：给一段带 bug 的代码，找出并修复），10 月起正式加入 |
| **根因分析** | 不满足于"改好了"，追问"为什么错" | 复盘笔记固定第三问："今天的问题，根因是什么？" |
| **审查逻辑** | AI 生成的代码逐行读懂、判断对错、发现边界问题 | 读-猜训练；10 月起 AI 生成代码一律先人工审查再运行 |

所以练习格式**不变**（读-猜→改→写→讲）："写"的比例会随 AI 使用而下降，但"读"和"猜"只会加重——**审的前提是能读**，看不懂代码的人无法审查 AI。语法查 [docs/python-grammar.md](docs/python-grammar.md)，像查字典。

**AI 协作规则（v3.1）**：
- 9 月：AI 可解释概念/报错/代码、出题考你；练习不要答案
- 10 月起：AI 可写代码，**你逐行审查后才运行**（审查=练习本身）；核心算法仍需能复述（面试防线）；上 GitHub 前无 AI 复写

**长期能力建设（研二全年，不随秋招结束）**：英语口语、根因分析方法论（8D/5Why 意识）、行业知识（光学计量标准、半导体工艺常识、工业相机/光源生态）、客户沟通表达。这些是入职后 1-3 年拉开差距的东西，秋招冲刺期只要求"有意识"，不要求速成。
